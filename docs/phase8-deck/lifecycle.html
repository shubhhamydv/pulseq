03 / EXECUTION LIFECYCLE
Every job follows a durable, observable lifecycle
SubmissionPersisted with idempotency key and schedule.
SchedulingRecurring scheduler or due-time queue makes work visible.
ClaimWorker lock plus atomic PostgreSQL transition.
ExecutionBounded handler invocation with attempt context.
OutcomeCompleted log, retry with jitter, or replayable DLQ.

What is durable?

Job state and execution history live in PostgreSQL, so a process restart does not erase the operational story.

What is fast?

Redis handles due-time visibility, priority metadata, locks, DLQ membership, and worker liveness.

What is observable?

Every attempt carries a worker identity, timing, status, and readable error context.

SUBMISSION → PERSISTENCE → SCHEDULING → CLAIM → EXECUTION → OUTCOME
